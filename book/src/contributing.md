# Participating

FerrionOS is developed by its maintainers, who introduce all changes to the codebase. The project does not accept pull requests from others.

Your involvement still moves the project forward:

- Bug reports with reduced test cases, and testing in virtual machines and on hardware
- Suggestions for features, designs and improvements
- Reference work: something you built in your own fork or project, linked from an issue for the maintainers to study
- Documentation improvements, including corrections to this book, proposed in an issue
- Security reports, made privately

The repository holds the rules, and this page only points to them:

| Document | What it covers |
|---|---|
| [CONTRIBUTING.md](https://github.com/CallMeOuta/FerrionOS/blob/master/CONTRIBUTING.md) | How to take part: the issue policy, reference work, the human language policy, and how the project is governed |
| [ISSUES.md](https://github.com/CallMeOuta/FerrionOS/blob/master/ISSUES.md) | What a bug report contains, and how to write a reduced test case |
| [SECURITY.md](https://github.com/CallMeOuta/FerrionOS/blob/master/SECURITY.md) | How to report a vulnerability privately, and the known limitations |
| [docs/code-policy.md](https://github.com/CallMeOuta/FerrionOS/blob/master/docs/code-policy.md) | How the maintainers make changes: testing, commits, and the use of AI and coding agents |

Bugs, suggestions and documentation improvements go to the [issue tracker](https://github.com/CallMeOuta/FerrionOS/issues). FerrionOS has no chat server.

Never report a security weakness in a public issue: follow SECURITY.md.

The chapters under [Developing for FerrionOS](./developing-for-redox.md) describe how to build, change and test the system in your own checkout.
