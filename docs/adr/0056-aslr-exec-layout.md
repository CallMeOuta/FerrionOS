# Per-process ASLR in the user-space exec path

Status: accepted

## Context

Previously, `redox_rt::proc::fexec_impl` placed every `ET_DYN` executable and dynamic linker (`ld.so`) via an unhinted anonymous mapping (always landing at `PAGE_SIZE` and right behind it), fixed every process stack at `STACK_TOP - STACK_SIZE..STACK_TOP`, left `target_args_env_address` (including `AT_RANDOM`) at the first free page, and wrote `grants_fd/mmap-min-addr` only for dynamically linked executables (`interp_override.is_some()`). Every invocation of a binary therefore observed the same virtual layout on every boot and every machine. Security item S10 splits into runtime ASLR in `redox-rt` (this record) followed by static PIE, default PIE compiler/linker flags, a per-recipe toggle and audit enforcement.

## Decision

- `fexec_impl` reads `EXEC_ENTROPY_BYTES = 48` bytes once per exec from `exec_random_bytes` (16 bytes for `AT_RANDOM` and four 64-bit seeds for PIE executable, `ld.so`, `mmap_min`, and stack top plus sub-page jitter) on the first call and carries the entropy buffer and `has_random` flag across `InterpOverride` to the interpreter call, adding zero `/scheme/rand` syscalls to dynamic exec.
- Narrow early-boot exemption: when `/scheme/rand` returns `ENODEV` under `is_early_boot_spawner()` (`ruid == 0`, `euid == 0`, and `pid == 1 || ppid == 1`, or freestanding builds without `proc`), `fexec_impl` preserves the fixed layout (`has_random = false`) using the exact same gate as [0037](0037-stack-guard-and-exec-entropy.md). That exemption covers `init` and the early initfs services started before `00_randd` registers `/scheme/rand` (`00_ipcd`, `00_logd`, `00_nulld`, `00_randd`, `00_rtcd`, `00_zerod`, and `ramfs@logging`). Every post-`randd` exec fails closed if `/scheme/rand` cannot be read.
- Named per-architecture layout constants partition the user address space into non-overlapping windows verified by compile-time assertions and runtime assertions in `fexec_impl`:
  - On 47-bit `x86_64` and `aarch64` (`STACK_TOP = 1 << 47`, 28 bits of page entropy = 1 TiB windows): PIE executables in `[16 TiB, 17 TiB)` (bounded below 20 TiB), `ld.so` in `[20 TiB, 21 TiB)` (bounded below 24 TiB), `mmap_min` in `[24 TiB, 25 TiB)`, reserved `ASLR_MMAP_BUDGET = 64 TiB` (~102 TiB actual free virtual space below the lowest stack for S14 `hardened_malloc` 32 GiB size-class reservations), and stack top in `[127 TiB, 128 TiB - KERNEL_METADATA_SIZE]` with 8 bits of 16-byte-aligned sub-page `sp` jitter taken from the unused upper bits (`stack_seed >> 56`) for 36 bits of total stack entropy.
  - On 38-bit `riscv64` Sv39 (`STACK_TOP = 1 << 38` = 256 GiB, 18 bits of page entropy = 1 GiB windows): PIE executables in `[16 GiB, 17 GiB)`, `ld.so` in `[24 GiB, 25 GiB)`, `mmap_min` in `[32 GiB, 33 GiB)`, `ASLR_MMAP_BUDGET = 192 GiB` (~222 GiB actual; S14's default 32 GiB-per-size-class `hardened_malloc` configuration does not fit in Sv39 and will require a smaller class region size on `riscv64`), and stack top in `[255 GiB, 256 GiB - KERNEL_METADATA_SIZE]` with 8-bit 16-byte sub-page jitter from `stack_seed >> 56`.
- `fexec_impl` maps each new stack page as a fresh grant instead of remapping the previous one when initial stack pushes cross a page boundary.
- `fexec_impl` reserves `[stack_top, STACK_TOP)` with a lazy `PROT_NONE | MAP_FIXED_NOREPLACE` ceiling grant (zero physical frames and zero page tables because `page_flags(PROT_NONE)` clears the user bit and sparse walks skip unallocated entries). Without that reservation, the kernel's best-fit `UserGrants::find_free_near` (`holes_by_size`) selects the smaller `< 1 TiB` hole above the randomized stack instead of the `> 64 TiB` region above `mmap_min`, placing `argv`/`envp`/`AT_RANDOM` and subsequent `mmap` calls above the stack.
- `fexec_impl` writes `grants_fd/mmap-min-addr` for every exec (both static and dynamic, not only `interp_override.is_some()`), before mapping `target_args_env_address`. On the early-boot fixed-layout path (`has_random = false`), `init` and the pre-`randd` static services therefore also receive `mmap-min-addr` set to the page-aligned end of the executable instead of keeping the kernel's default floor. Because the kernel's `find_free` and `find_free_near` honour `mmap_min` as a strict lower bound, `target_args_env_address` (holding `argv`, `envp`, and `AT_RANDOM`), `ld.so` `dlopen`/shared-library mappings, `dlmalloc` allocations, and anonymous `mmap` calls all land at or above the floor, and no unmapped hole between the executable and `ld.so` can undermine randomization.
- `fexec_impl` asserts at runtime that the executable, interpreter, and stack ranges do not overlap, that `mmap_min` is page-aligned and at or above the end of every executable and interpreter mapping, that `stack_bottom >= mmap_min + ASLR_MMAP_BUDGET` for standard layouts (`exec_end <= ASLR_MMAP_BASE`), and that `target_args_env_address` lies in `[mmap_min, stack_bottom]`. For high-linked fixed `ET_EXEC` binaries placed above `ASLR_MMAP_BASE` (notably `linux-run`, linked at `0x7000_0000_0000` so the lower 112 TiB stays free for Linux guest images), `fexec_impl` randomizes `mmap_min` above `exec_end` within `min(ASLR_MMAP_WINDOW, avail - ASLR_HIGH_EXEC_MMAP_BUDGET)` and asserts `ASLR_HIGH_EXEC_MMAP_BUDGET = 64 MiB` minimum headroom below `stack_bottom` (~14 TiB actual for `linux-run`).
- Exhaustion fails closed: `mmap_anon_remote_aslr` retries `MAP_FIXED_NOREPLACE` up to `ASLR_MAP_MAX_TRIES = 16` times using `splitmix64` steps and returns `ENOMEM` on exhaustion rather than falling back to a fixed address.
- Private auxiliary vector tag `AT_REDOX_STACK_BASE = 46` (the next free slot after `AT_REDOX_FILETABLE_FD = 45` in `components/relibc/src/platform/auxv_defs.rs`) carries the main thread's randomized `stack_bottom` to `relibc::pthread::init`, replacing the hardcoded `STACK_TOP - STACK_SIZE` so `pthread_getattr_np` and `pthread_attr_getstack` match the live stack. This tag is private to native FerrionOS executables; `linux-run` constructs its own Linux auxiliary vector, so Linux-ABI programs never see it (Linux assigns 40..47 to cache geometry).
- No runtime ASLR toggle is added in this slice; `fork` without `exec` continues to inherit the parent's address space layout as on Unix.

## Consequences

- Every post-`randd` process (both `posix_spawn` / `fork`+`exec` and same-process `execve`) receives independent randomized stack, `malloc`, `mmap`, `AT_RANDOM` pointer, and `dlopen` DSO addresses; dynamically linked PIE executables (all 48 dynamic Rust programs in `minimal` and PIE C binaries) also randomize `main` and `ld.so`, while non-PIE static binaries keep `main` fixed until static PIE lands.
- What breaks: because the kernel's non-fixed `mmap` hint path (`find_free_near`) enforces `mmap_min` as a hard floor, programs requesting a low address hint below 24 TiB without `MAP_FIXED` or `MAP_FIXED_NOREPLACE` receive an address at or above `mmap_min` instead. Neither `minimal` nor `desktop` ships `luajit`, `nodejs-21`, or `webkitgtk3`; `desktop` (`boot`, `exec-handles`, `linux-hello`) and `stack-guard` (`canary-random`, `stack-smash-aborts`) pass with ASLR enabled, and `linux-dynamic`'s dynamic glibc, pthread, `posix_spawn`, and Debian coreutils invocations all exit 0 with empty stderr (its only failure is a pre-existing `/usr/lib/x86_64-linux-gnu` directory-count drift in `linux-lc3-fixtures`). If a JIT port later requires a low-address hint without `MAP_FIXED`, that breakage is the justification for a per-program runtime toggle.
- Spreading executable, `ld.so`, `mmap`, and stack across separate 1 TiB regions adds a small number of intermediate page-table pages per process. Measured back-to-back in a quiet window on QEMU 11.1.3 (`x86_64`):
  - `aslr` 8-run distinctness: dynamic PIE 8/8 distinct on `main`, `stack`, `stack_base`, `malloc`, `mmap`, `dso`, `at_random_ptr`, and `at_random_val` (before: 1/8 on all addresses); static non-PIE `main` fixed at `0x407aa0` and 8/8 distinct on all other addresses (before: 1/8); same-process `execv` (`reexec`) randomizes all layout addresses (before: unchanged); `fork` without `exec` preserves layout; `pthread_getattr_np` matches the live stack on every run.
  - Exec latency (`aslr-bench`, 256 runs each, before -> after): `aslr-true-static` median 3199 -> 2947 us (-7.9%), p95 3364 -> 3172 us (-5.7%), p99 3809 -> 3292 us (-13.6%) (within run-to-run variance); `aslr-true-dynamic` median 4560 -> 4564 us (+4 us, +0.1%), p95 5119 -> 5264 us (+145 us, +2.8%), p99 5511 -> 5432 us (-79 us, -1.4%).
  - `desktop` image memory at idle login (`free`): used 184448 KiB -> 185096 KiB (+648 KiB, +0.35%; free 1858908 KiB -> 1858228 KiB), confirming zero physical frame allocation for the `PROT_NONE` stack ceiling grant.
