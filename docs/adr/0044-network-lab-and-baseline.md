# Network test lab, probe and baseline method

Status: accepted

## Context

FerrionOS's network stack and drivers need reproducible checks for full-size frames, idle round-trip latency, TCP window scaling, socket options, name-lookup matching, per-session views and throughput on both virtual network cards (`e1000` and `virtio-net`). QEMU's user-mode network uses a 24-hour DHCP lease, lacks a time server, hides packet-level behavior behind libslirp and cannot host a second routed subnet. Running a bridge or tap device as host root is neither repeatable nor acceptable in an unprivileged development environment.

## Decision

- **Unprivileged lab namespace (`scripts/net_lab.py`, `scripts/vm-test.py --lab`).** Tests that need the lab re-exec `scripts/vm-test.py` under `unshare --user --map-root-user --net --kill-child`, with no route out. Inside the namespace, `10.77.0.1/24` and `10.77.0.54/24` sit directly on `tap0` (no `bridge` module required for a single guest), and `198.51.100.1/32` sits on `lo` to stand for a routed internet destination reachable through the guest's default route (`10.77.0.1`). `dnsmasq` serves 2-minute DHCP leases (`10.77.0.50`–`10.77.0.99`) naming `10.77.0.1` as router and DNS server. QEMU boots with `net=no`, `-netdev tap,ifname=tap0,script=no,downscript=no`, and `filter-dump` packet capture for `net-basics` (omitted in `net-perf` so throughput runs do not write multi-gigabyte captures).
- **Two reported topologies, never mixed.** Topology A (`lab_tap`) runs guest-to-host over `tap0`. Topology B (`qemu_user`) runs QEMU's `-netdev user` inside the same isolated network namespace (which has only `lo` and `tap0` and no route out) so `10.0.2.2` reaches helpers bound to the namespace's `127.0.0.1` while nothing can leave the host.
- **Preflight and `BLOCKED`.** Before booting, `scripts/net_lab.py` checks required host tools (`unshare`, `ip`, `tc`, `dnsmasq`, `ping`, and `iperf3` for `net-perf`) via `shutil.which`, checks unprivileged user namespaces, and checks `tap0` creation and `tc netem` inside the namespace. Any missing tool or unavailable kernel feature raises `Blocked` (exit code 2) naming the missing dependency. Entering `--in-lab` brings `lo` up immediately so mixed invocations do not bind a down loopback interface.
- **Single card per invocation.** `net-basics` and `net-perf` run one network card per invocation, selected by `--make net=` (`e1000` by default, or `virtio`), matching `net-hardening` so `--repeat`, `result.json` and quiet-host timing windows remain per card.
- **Network probe (`recipes/tests/net-probe`).** A standalone Rust crate depending only on `libc = "0.2.191"` that issues direct `libc` socket calls (exposing exact `call`, `errno`, symbolic `error` name and `strerror` text on failure) and emits one JSON object per run. All counts, payload sizes, timeouts and iteration loops carry explicit TigerStyle bounds (`MAX_COUNT = 100_000`, `MAX_BYTES = 65_507`, `MAX_TIMEOUT_MS = 60_000`; exhausting `MAX_ECHO_STEPS` returns `EOVERFLOW` rather than `ETIMEDOUT`). The 99.9th percentile (`p999_ms`) is reported only when at least `10_000` samples were collected (`null` otherwise).
- **Test image (`config/x86_64/net-test.toml`).** Extends `config/x86_64/desktop.toml` with `net-probe` and `iperf3` (pinned by `blake3` and verified against iperf3's published `.sha256`, with `recipes/tests/iperf3/ferrion-port.patch` replacing unbuffered `fread("/dev/urandom")` with bounded `open`/`read`, adding `<stdlib.h>` and replacing `sscanf("%lf%c")` with `strtod` in `units.c`, and replacing `pthread_cancel` with `shutdown` plus `pthread_join`). No lab test CA is committed in NW0: nothing in NW0 or NW1 uses TLS, and future TLS/NTS checks (NW3, NW4) will generate ephemeral per-run keys and install only the certificate into the `-snapshot` guest.
- **No duplicate ARP flood.** `net-basics` reports all nine NW1 items individually and reuses `scripts/vm-test.py`'s `consecutive_run`, `pcg_prediction` and `dns_reply` helpers; item 9 (ARP cache growth bound) checks `net-hardening-1/result.json` only when its `make` list names the same `net=` card and its timestamp is newer than `build/<arch>/<config>/harddrive.img` (otherwise item 9 fails with `"net-hardening not run on this image and card"`).
- **Repeatability, priority and load gating (`net-perf` and timed `net-basics` items).** Every `iperf3` sample verifies `start.test_start`'s `blksize`, `target_bitrate`, `num_streams`, `omit` and `duration` against the requested parameters before accepting it. Multi-stream and latency series retry transient failures up to a bounded cap (`MAX_IPERF_ATTEMPTS = 5`) to collect 3 valid samples, record `runs_completed`, `runs_requested` and `attempts`, and any measure with fewer than `runs_requested` valid samples is excluded from agreement counts. Every measure records card, `vhost=off`, QEMU and `iperf3` versions (`guest_iperf3` parsed via `iperf\s+\d+\.\d+\S*`), component commits, guest CPU time deltas from `/scheme/sys/context` (`ACTTIME`, for processes alive before and after) plus `iperf3`'s `end.cpu_utilization_percent`, live QEMU thread `nice` and scheduling policy from `/proc/<pid>/task/*/stat` plus the host `iperf3` servers' `nice` and policy, and host one-minute load before and after. Each `net-perf` pass and each timed `net-basics` item (2, 3 and 7) scans `/proc` before and after every sample for any foreign `qemu-system-*` process outside its own child tree (recording PID, start time and cwd) and checks an optional `--window-deadline` timestamp; `net-perf` aborts immediately on the first foreign QEMU so the quiet window is freed at once. The `/proc` detector matches `qemu-system-*` processes only, so another VMM or a host cook is caught only through the load limit and the quiet registry. Any pass exceeding load 12.0, overlapping a foreign QEMU, finishing past its window deadline, missing a recorded QEMU priority (`priority_unrecorded`), or changing QEMU `nice`/policy mid-pass (`nice_changed`) is marked `host_limited` and raises `Blocked` (exit code 2); comparing passes when either pass is `host_limited` or when their recorded QEMU `nice`/policy differ or are missing also reports `BLOCKED` (exit code 2). An explicit `--legacy-unrecorded-nice` flag on `--compare-net-perf` permits comparing only pre-guard passes whose `conditions` lack `qemu_priority`, `foreign_qemu` and `window_deadline` keys (printing `nice not recorded` in its verdict); those four NW0 passes carry `not recorded` for `nice` in `docs/vm-baseline.md`. Two qualified passes with the same QEMU `nice` and policy agree (`--compare-net-perf` or `--repeat 2`) when for every comparable numeric measure `|median_1 - median_2| <= max(0.10 * max(|median_1|, |median_2|), spread_1, spread_2)`, where `spread` is `max - min` across the pass's 3 runs.

## Consequences

- Network functional and performance checks run without host root and cannot leak traffic off the host.
- Missing host tools or disabled user namespaces report `BLOCKED` (exit 2) cleanly without starting QEMU.
- Baseline numbers in `docs/vm-baseline.md` carry explicit conditions and a machine-checked repeatability rule so NW1 and later slices can compare against them objectively. For NW0's initial four passes (compared with `--legacy-unrecorded-nice`), the "twice within noise" target is met for `e1000` (17 of 17 comparable measures; `lab_tap.tcp_1b_echo` completed 2 of 3 runs in Pass 2 and is excluded from the checked count) and not met for `virtio-net` (16 of 18; misses on `lab_tap.tcp_rx_rtt50ms` and `qemu_user.tcp_tx_4`, both documented in `docs/vm-baseline.md`).
