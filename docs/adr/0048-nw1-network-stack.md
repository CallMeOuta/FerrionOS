# 0048: Network Stack Transport, Wakeups, Socket Options, and Interface Enumeration (NW1)

Date: 2026-11-23
Status: Accepted

## Context

NW0 ([ADR 0044](0044-network-lab-and-baseline.md)) established the repeatable network lab, `net-basics`, and `net-perf` baselines on both `e1000` and `virtio`. Those measurements exposed concrete transport, driver wakeup, socket-option, DNS, and interface-enumeration gaps in `netstack`, `virtio-netd`, `virtio-core`, `relibc`, and `linux-run`.

This record documents the NW1 design decisions, bounds, error contracts, and deliberate limits across those components.

## Decisions

### Monotonic stack clock

`netstack` captures one monotonic `std::time::Instant` at startup, initializes the `smoltcp` interface at `Instant::ZERO`, and advances it with elapsed monotonic microseconds on every `poll()` and before TCP scheme requests (`poll_maintenance`). It never derives engine timestamps from `SystemTime`, so wall-clock adjustments in later slices cannot shift TCP timers or sequence-number clocks.

### Bounded scheme turns and timer re-arming

`Smolnetd` serves each socket scheme in bounded turns: `MAX_SCHEME_REQUESTS_PER_BATCH = 64` requests per `poll()` call so a burst of rapid socket syscalls yields regularly to packet processing and loopback delivery, and `MAX_SCHEME_BATCHES_PER_EVENT = 16` batches (1,024 requests) per event before setting `pending_scheme_events` and yielding back to the main event loop. Those bounds keep the steady-state fast path to a single `poll()` per burst while guaranteeing progress for the NIC, timer, and other schemes under continuous request traffic. When `pending_scheme_events` is set, the timer handler services the four socket schemes (`ip`, `udp`, `tcp`, `icmp`) and omits `netcfg`, which is root-only and never receives untrusted request storms.

Because `/scheme/time` registers each write as an independent kernel timeout, `Smolnetd` tracks armed deadlines in a sorted list capped at `MAX_PENDING_TIMERS = 32` (`arm_timer`). Expired deadlines at or before `now` are dropped on each timer event, and `arm_timer` writes to `/scheme/time` only when the requested wake time is strictly earlier than every deadline still armed and the list is below the cap. Both the zero-delay yield path and post-poll re-arming on network, scheme, and timer events go through `arm_timer`, so pending kernel timeouts remain bounded and return to baseline when idle. Spurious timer wakeups when nothing is due are harmless.

### `virtio-netd` direct IRQ wakeup and TX buffer pool

In `ferrion-hardware` (the `virtio-netd` RX wakeup, TX buffer pool, and direct IRQ commits pinned by `recipes/core/drivers/recipe.toml`), `virtio-core` exposes opt-in `Device::setup_queue_manual_irq()`, `Queue::set_no_interrupt()`, and `VolatileCell::set_shared()` (leaving `Device::setup_queue()` and `virtio-gpud` unchanged; the direct-IRQ commit removes the earlier pipe notifier from `transport.rs`, leaving `transport.rs` as upstream plus `set_no_interrupt` and `setup_queue_unattached`). `virtio-netd` runs single-threaded (matching `e1000d`), subscribing `rx_irq` directly alongside its scheme handle in `/scheme/event` before entering the null namespace (`setrens(0, 0)`), and keeps TX interrupts suppressed (`VRING_AVAIL_F_NO_INTERRUPT`).

To avoid blocking `virtio-netd`'s event loop on TX completions or allocating DMA pages per packet, `VirtioNet` pre-allocates a bounded pool of single-descriptor TX DMA buffers (`MAX_TX_POOL_BUFFERS = 64`, `TX_POOL_BUF_LEN = 4096`, reserving two descriptors for fallback), reclaims completed slots via `tx.pop_completed()`, and submits pooled frames with `tx.post()`. When the pool is empty, `virtio-netd` polls for TX completions up to `MAX_TX_RECLAIM_POLLS = 1024` times, then answers `EAGAIN` and `netstack` drops the frame (the fallback path for frames above `TX_POOL_BUF_LEN - size_of::<VirtHeader>()` uses the same bounded poll and cannot run for Ethernet frames up to 1,514 bytes).

### ICMP echo replies

`netstack` enables `smoltcp`'s `auto-icmp-echo-reply` feature so `eth0` responds to ICMPv4 echo requests, including full-size 1,472-byte unfragmented frames. Replies follow the route table for the configured `eth0` address.

### TCP socket buffers and post-connect updates

TCP sockets default to `TCP_DEFAULT_RX_BUF_BYTES = 1 MiB` (`1,048,576` bytes, keeping RFC 7323 window scaling and the high-latency BDP gain) and `TCP_DEFAULT_TX_BUF_BYTES = 256 KiB` (`262,144` bytes), for `1.25 MiB` per TCP socket (clamped to `TCP_MIN_BUF_BYTES = 16 KiB` through `TCP_MAX_BUF_BYTES = 4 MiB`). Because `relibc`'s `dlmalloc-rs` has no direct-`mmap` path, `calloc` (and therefore Rust's `vec![0; N]`) zeroes and faults every page at socket creation; lowering the send default from `1 MiB` to `256 KiB` cuts idle per-socket resident memory from `2 MiB` to `1.25 MiB` at a modest bulk-TX cost documented in Verification below. The send default will rise once large allocations get their own mapping in a separate post-cutover `relibc` slice. Buffers requested via `SO_RCVBUF`/`SO_SNDBUF` before connect or bind are applied on socket creation and inherited by replacement listeners; calls on already-connected sockets validate arguments and succeed (`0`) while `getsockopt` continues reporting the actual `recv_capacity()`/`send_capacity()`.

### TCP close and bounded lingering table

When the last handle to a TCP socket closes, `netstack` calls `TcpSocket::close()` so a `FIN` is transmitted. Sockets not yet `Closed` move into a bounded lingering table (`MAX_LINGERING_SOCKETS = 64`, `LINGER_TIMEOUT_US = 15_000_000`) while retaining their port reservation until `Closed` or timeout, at which point they are aborted and removed. When the table reaches `MAX_LINGERING_SOCKETS`, the oldest lingering socket is aborted and removed to make room. Every `abort()` in the lingering table is followed immediately by `remove()`, so no `RST` is transmitted; the peer learns only when it next sends. Accepted TCP sockets are tracked with accurate reference counts and freed on close.

### Socket options, errors, connect timeout, and listen queue

`relibc` forwards `setsockopt`/`getsockopt` level as the third metadata word for `AF_INET` sockets (encoding `IPPROTO_IP = 0` as `u64::MAX`, rejecting negative levels with `ENOPROTOOPT`, and passing positive levels directly so `netstack` can treat a zero-padded third word `0` from pre-NW1 binaries as legacy `SOL_SOCKET`; `AF_UNIX` retains `SO_ERROR = 0` and `SOL_SOCKET`-only behavior), returns `EINPROGRESS` on non-blocking `AF_INET`/`SOCK_STREAM` `connect()`, and dispatches `listen()` on `AF_INET`/`SOCK_STREAM` via scheme call verb `10`. Verb `10` for `listen` extends upstream's `SocketCall` numbering privately (`libredox` 0.2.0 ends at `Shutdown = 9`) and must be rechecked at each upstream sync.

`netstack` honors:
- `SOL_SOCKET`: `SO_REUSEADDR` (allows binding a port held only by lingering sockets, not active or listening sockets), `SO_KEEPALIVE` (TCP), `SO_RCVBUF`, `SO_SNDBUF`, `SO_RCVTIMEO`, `SO_SNDTIMEO`, and read-only `SO_ERROR` (clear-on-read, signaling `EVENT_ERR` alongside requested read/write events on completion failure).
- `IPPROTO_TCP`: `TCP_NODELAY` (controls Nagle) and `TCP_KEEPIDLE` (`1..=86400` seconds, applied as the `smoltcp` keepalive interval when `SO_KEEPALIVE` is enabled).

Unsupported levels or options return `ENOPROTOOPT`. Outbound TCP connects carry a `TCP_CONNECT_TIMEOUT_SECS = 30` second timeout (`ETIMEDOUT`), peer resets during connect report `ECONNREFUSED` in `SO_ERROR`, and peer resets on established sockets report `ECONNRESET` on the next read or write instead of `ENOTCONN`.

`listen(backlog)` sizes a bounded pool of listening `smoltcp` sockets capped by both `MAX_LISTEN_BACKLOG = 64` and a per-listener byte budget `MAX_LISTEN_POOL_BYTES = 8 MiB`: `budget_cap = (MAX_LISTEN_POOL_BYTES / (rx_buf_bytes + tx_buf_bytes)).clamp(1, MAX_LISTEN_BACKLOG)` and `target = backlog.clamp(1, budget_cap)`. The budget's unit is pre-allocated socket buffer capacity (`rx_buf_bytes + tx_buf_bytes` across all pool slots) rather than queued payload bytes, because `smoltcp` allocates fixed buffers when each listening socket is created at `listen()` time and `relibc`'s `calloc` faults those pages eagerly. At the default `1 MiB` RX / `256 KiB` TX (`1.25 MiB` per socket), the effective backlog is `6` pending connections (`7.5 MiB` total resident buffer capacity, capping unaccepted remote-queued RX bytes at `6 MiB`), down from `128 MiB` resident at `64 * 2 MiB`; callers that lower `SO_RCVBUF`/`SO_SNDBUF` before `bind`/`listen` scale up to `64` slots within `8 MiB` (for example `64 KiB` RX + `64 KiB` TX permits all `64` slots). Once all pool slots are active, further SYNs are refused by `smoltcp`; NW5 adds global per-view socket and memory bounds across listeners and lingering sockets.

Listening sockets report readable and are returned by `accept()` only after the three-way handshake completes (`is_accept_ready`: `is_active() && state() != TcpState::SynReceived`), and `TcpSocket`'s `read_buf` and `is_readable` dispatch `<Self as SchemeSocket>::may_recv` rather than `smoltcp`'s inherent `may_recv()` (which returns `false` in `SynReceived` and `SynSent`), preventing immediate spurious `POLLIN` / `Ok(0)` EOF when `accept()` outraces the client's final `ACK`.

`linux-run` replays supported options onto native sockets before connecting, forwards runtime option changes, reads live `SO_ERROR` and buffer sizes from native sockets, and defaults fallback `SO_RCVBUF` to `1 MiB` and `SO_SNDBUF` to `256 KiB` when no live native socket exists.

### Unconfigured link and error handling

When no source address or route exists for a TCP destination (for example, an unconfigured `eth0` with no DHCP lease), `netstack` returns `ENETUNREACH` (`EADDRNOTAVAIL` or `EINVAL` on endpoint/state errors) without terminating the daemon, and ignores unsupported memory-map scheme messages. Unbounded request wait-queue growth is left to NW5's per-view bounds.

### DNS retry and TCP fallback

`relibc`'s resolver performs up to `MAX_UDP_ATTEMPTS = 2` UDP queries within the 7-second total deadline (`3 s` first attempt, remaining budget second attempt), choosing a fresh transaction ID and random ephemeral source port on each attempt. When a matched UDP reply sets the `TC` truncation bit, it falls back to TCP port 53 with 2-byte length framing capped at `MAX_TCP_DNS_LEN = 65535` bytes and `MAX_TCP_DNS_READS = 512` reads inside the remaining deadline.

### IPv4 `getifaddrs` and `net_if`

`relibc` implements IPv4-only `getifaddrs` (no `AF_PACKET`/`AF_LINK`, `ifa_data` null) using a single `malloc` block per entry (`IfaddrsEntry`) so unchanged `freeifaddrs` frees every node without leaks, bounded by `MAX_IFADDRS_ENTRIES = 16` (`ENOMEM`), `MAX_NETCFG_BYTES = 1024`, and `MAX_NETCFG_READS = 32` (`EIO`):
- `lo` (`127.0.0.1/8`, null broadcast) carries `IFF_UP | IFF_LOOPBACK | IFF_RUNNING` when `/scheme/udp` or `/scheme/tcp` can be opened, and `IFF_LOOPBACK` alone when network schemes are withheld (for example `ferrion-run --no-network`).
- `eth0` is read from `/scheme/netcfg/ifaces/eth0/addr/list` with `IFF_UP | IFF_BROADCAST | IFF_RUNNING` (no `IFF_MULTICAST`, as `e1000d` leaves multicast off; `IFF_RUNNING` does not yet reflect live carrier state because current NIC drivers do not expose link state). Unconfigured, missing, or inaccessible `netcfg` omits `eth0` without failing; malformed content returns `EIO` with `*ifap = NULL`. Because ordinary login namespaces (`user`) and browser sandboxes do not hold `netcfg`, only root observes `eth0` until NW2 replaces this source with `netd`'s read-only status scheme.
- `if_nameindex`, `if_nametoindex`, and `if_indextoname` expose `lo` (index `1`) and `eth0` (index `2`), replacing the previous `stub` entry. Native `getifaddrs` and `linux-run`'s netlink dumps remain independent until NW2.
